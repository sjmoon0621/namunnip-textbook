  2. 복원함수를 호출하면 새 프레임이 생기고, 함수가 끝나면 프레임이 사라지며 값이 호출한 곳으로 돌아갑니다. 수학에서 n! = n × (n − 1)!, 0! = 1입니다.
    3. 
      
  3. 설명자기 자신을 호출하는 함수를 재귀 함수라 합니다. 재귀 함수에는 두 부분이 꼭 있어야 합니다. 더 쪼개지 않고 바로 답을 내는 기저 조건과, 문제를 크기가 더 작은 같은 문제로 바꾸어 자기를 부르고 그 결과를 조합하는 재귀 단계입니다. 호출이 이어질 때마다 프레임이 호출 스택에 쌓이고, 각 프레임은 자기만의 n을 가집니다. 기저 조건에 닿으면 가장 나중에 쌓인 프레임부터 값을 돌려주며 차례로 빠집니다.
    4. 
      
  4. 연결재귀 함수는 수학적 귀납법과 같은 구조입니다. 기저 조건은 귀납법의 첫 단계(n = 0일 때 성립)이고, 재귀 호출 fact(n - 1)은 귀납 가정(“n − 1에 대해서는 맞다”)에 해당합니다. 그래서 재귀 함수를 설계할 때는 호출 과정을 끝까지 따라가지 않고, “더 작은 문제의 답은 재귀 호출이 이미 맞게 구해 준다”고 믿은 뒤 그 답으로 지금 문제를 어떻게 푸는지만 정하면 됩니다. 이 관계를 식으로 쓴 것이 재귀 관계 f(n) = n × f(n − 1)입니다.
    5. 
      
  5. 적용세 함수를 실행하며 오른쪽 식의 전개를 보세요. 각 함수에서 재귀 관계는 무엇인가요? 인자를 바꾸며 최대 스택 깊이를 기록하세요. 팩토리얼과 리스트 합은 인자에 비례해 깊어지는데, 이진수 변환은 n을 64까지 키워도 왜 7을 넘지 않나요? ‘기저 조건 지우기’를 켜고 세 함수가 각각 어떻게 실패하는지 비교하세요.
    6. 
      
  6. 판단기저 조건이 있어도 인자가 그 조건에 다가가지 않으면 끝나지 않습니다. fact(-1)은 n이 −2, −3, …으로 작아지기만 해서 n == 0에 닿지 못합니다. 조건을 n <= 0으로 쓰거나 음수를 미리 걸러야 합니다. 또 파이썬은 스택 깊이를 기본 1000 정도로 제한하므로, 깊이가 입력 크기에 비례하는 재귀는 큰 입력에서 RecursionError를 낼 수 있습니다.

def count_down(n):
    if n == 0:
        return
    count_down(n - 1)
    print(n)
