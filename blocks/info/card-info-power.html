3의 1000제곱을 곱셈 몇 번으로 구할 수 있을까?

분할 정복 · 부분 문제의 답 재사용 · 거듭제곱

반복문으로 a를 곱하기
—
power(n//2)를 두 번 호출
—
half에 저장해 한 번 호출
—
n의 2진수
—

        
세 칸의 숫자는 곱셈 횟수입니다. "두 번 호출"은 half를 쓰지 않고 return power(a, n // 2) * power(a, n // 2)처럼 쓴 경우입니다. 파이썬의 정수는 자릿수 제한이 없어 큰 값도 정확히 구하지만, 자릿수가 커지면 곱셈 한 번도 오래 걸립니다. 실제로는 pow(a, n) 또는 a ** n을 씁니다.

      

    

    
    
      
  1. 질문3¹⁰⁰⁰을 구하려고 3을 계속 곱하면 곱셈 999번이 필요합니다. 그런데 3¹⁰⁰⁰ = (3⁵⁰⁰)²이므로 3⁵⁰⁰만 알면 곱셈 한 번으로 끝납니다. 이렇게 계속 나누면 곱셈이 몇 번으로 줄어들까요?
    2. 
      
  2. 복원분할 정복은 문제를 작은 부분 문제로 나누고, 그 답을 결합해 전체 답을 만듭니다. 지수 법칙에 따라 a2m = (am)², a2m+1 = (am)² × a입니다.
    3. 
      
  3. 설명power(a, n)은 부분 문제 power(a, n // 2)의 답 half를 구한 뒤, n이 짝수면 half × half, 홀수면 half × half × a를 돌려줍니다. 지수가 매번 반으로 줄므로 호출은 약 log₂n번만 쌓이고, 한 층에서 곱셈은 1~2번입니다. 각 줄의 n을 2진수로 보면 한 줄 내려갈 때마다 맨 오른쪽 자리가 하나씩 떨어집니다. 그래서 곱셈을 두 번 하는 홀수 단계(주황)의 수는 n의 2진수에 있는 1의 개수와 같습니다.
    4. 
      
  4. 연결합병 정렬은 크기가 반인 부분 문제 두 개를 풀어야 하지만, 거듭제곱은 같은 부분 문제 하나의 답을 두 번 쓰면 됩니다. 그 답을 변수 half에 저장하지 않고 power(a, n // 2)를 두 번 부르면, 호출 수가 층마다 두 배로 늘어 결국 곱셈 횟수가 반복문과 비슷하거나 오히려 많아집니다. 분할 정복의 효율은 부분 문제의 개수, 크기가 줄어드는 비율, 결합 비용이 함께 정합니다.
    5. 
      
  5. 적용a = 3, n = 13에서 한 단계씩 실행하며 호출이 쌓였다가 아래에서부터 값이 돌아오는 순서를 확인하세요. n을 1000으로 놓고 세 방법의 곱셈 횟수를 비교하세요. n = 1023과 n = 1024 중 한 번 호출 방법의 곱셈이 더 많은 쪽은 어디이고, 왜 그런지 2진수로 설명해 보세요.
    6. 
      
  6. 판단곱셈 횟수가 줄었다고 실행 시간이 꼭 그만큼 주는 것은 아닙니다. 3¹⁰⁰⁰은 478자리 수라서 곱셈 한 번도 작은 수의 곱셈보다 훨씬 오래 걸립니다. 그래도 같은 수를 반복해서 곱하는 방법보다는 훨씬 빠르며, 암호에서 쓰는 "aⁿ을 m으로 나눈 나머지" 계산은 매 단계 나머지만 남겨 수가 커지지 않게 하면서 이 방법을 그대로 씁니다(파이썬의 pow(a, n, m)).
