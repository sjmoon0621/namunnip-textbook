버그는 어떤 순서로 잡아야 할까?

읽기 · unittest로 테스트 자동화, 디버깅 과정

프로그램이 틀린 답을 냅니다. 코드를 처음부터 눈으로 다시 읽으면 찾을 수 있을까요? 코드가 수백 줄이 넘으면 그렇게 해서는 끝이 나지 않습니다.

1테스트를 코드로 남기기

테스트를 손으로 매번 입력하면 귀찮아서 결국 덜 하게 됩니다. 파이썬 표준 라이브러리의 unittest로 테스트를 파일에 적어 두면, 명령 한 줄로 언제든 모두 다시 돌릴 수 있습니다.

import unittest
from stats import median

class TestMedian(unittest.TestCase):
    def test_odd(self):
        self.assertEqual(median([3, 1, 2]), 2)

    def test_even(self):                        # 경계: 짝수 개
        self.assertEqual(median([4, 1, 3, 2]), 2.5)

    def test_empty(self):                       # 예외 경우
        with self.assertRaises(ValueError):
            median([])

if __name__ == "__main__":
    unittest.main()

실행하면 통과한 테스트는 점(.)으로, 실패한 테스트는 F, 예상하지 못한 오류는 E로 표시되고, 실패한 테스트마다 기대값과 실제 값을 보여 줍니다. 버그를 고칠 때마다 이 파일을 다시 돌리면 회귀 테스트가 됩니다. 실무에서는 pytest처럼 더 간결하게 쓰는 외부 라이브러리도 많이 씁니다.

2디버깅의 순서

  • 재현: 버그가 언제나 나타나는 가장 작은 입력을 찾습니다. 그 입력을 그대로 테스트로 만들어 둡니다.
  • 범위 좁히기: 중간 값을 print로 찍거나, 개발 환경의 디버거로 중단점(breakpoint)을 걸고 한 줄씩 실행하며 변수를 봅니다. 값이 처음으로 예상과 달라지는 줄 근처에 원인이 있습니다. 코드의 절반씩을 확인해 나가면 이진 탐색처럼 빠르게 좁혀집니다.
  • 원인 이해: 증상(틀린 출력)이 아니라 원인(잘못된 조건, 경계 처리, 자료형)을 찾습니다. 왜 틀렸는지 설명할 수 있어야 제대로 고친 것입니다.
  • 수정과 확인: 고친 뒤 재현 테스트가 통과하는지, 기존 테스트도 모두 통과하는지 확인합니다.
  • 기록: 커밋 메시지나 이슈에 무엇이 원인이었고 어떻게 고쳤는지 남깁니다.
오류의 종류언제 드러나나예
문법 오류실행 전에 바로콜론 빠짐, 괄호 짝이 맞지 않음 (SyntaxError)
실행 중 오류그 줄이 실행될 때0으로 나눔 (ZeroDivisionError), 없는 인덱스 (IndexError)
논리 오류오류 메시지 없이 답이 틀림<=를 <로 씀, 400년 규칙 빠뜨림

판단논리 오류가 가장 찾기 어렵습니다. 프로그램이 아무 말 없이 틀린 답을 내기 때문입니다. 그래서 정답을 알고 있는 입력으로 테스트를 미리 만들어 두는 것이 중요합니다. 또 버그를 고치려다 코드를 이것저것 동시에 바꾸면 무엇이 효과가 있었는지 알 수 없으니, 한 번에 하나씩 바꾸고 확인합니다.
