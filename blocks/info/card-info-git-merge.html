두 사람이 같은 파일을 고치면 git은 어떻게 합칠까?

오픈소스 협업 · 브랜치, 병합, 충돌

main 브랜치 (민지가 고침)

fix-empty 브랜치 (준호가 고침)

브랜치마다 고칠 줄을 고른 뒤 병합하세요.


        
stats.py의 처음 내용(공통 조상)에서 두 브랜치가 갈라졌습니다. 파란 띠는 main의 변경, 노란 띠는 fix-empty의 변경입니다. 실제 git처럼 같은 줄이나 바로 붙은 줄을 양쪽이 서로 다르게 고치면 충돌로 처리합니다.

      

    

    
    
      
  1. 질문오픈소스 프로젝트에는 서로 만난 적 없는 수백 명이 코드를 고칩니다. 두 사람이 같은 파일을 동시에 고치면, 한 사람의 수정이 다른 사람의 수정을 덮어써 버리지 않을까요?
    2. 
      
  2. 복원git은 파일의 변경 이력을 커밋 단위로 저장하는 버전 관리 도구입니다. 브랜치는 커밋 이력의 갈래로, 각자 자기 브랜치에서 작업하면 남의 작업과 섞이지 않습니다. GitHub, GitLab 같은 서비스는 git 저장소를 인터넷에 두고 함께 쓰게 해 줍니다.
    3. 
      
  3. 설명병합(merge)할 때 git은 두 브랜치의 마지막 커밋과 둘이 갈라진 공통 조상, 세 가지를 비교합니다(3-way merge). 한쪽만 고친 부분은 고친 쪽을 자동으로 택하고, 양쪽이 같은 곳을 서로 다르게 고쳤으면 어느 것을 택할지 판단하지 못해 충돌(conflict)을 알립니다. 충돌한 곳에는 <<<<<<<, =======, >>>>>>> 표시가 들어가며, 사람이 내용을 보고 고친 뒤 커밋해야 병합이 끝납니다.
    4. 
      
  4. 연결오픈소스 협업에서는 보통 저장소를 복제(fork)하거나 브랜치를 만들어 고친 뒤 풀 리퀘스트(pull request)로 병합을 요청합니다. 다른 사람이 코드를 검토(code review)하고 자동 테스트가 통과하면 병합합니다. 작은 단위로 자주 커밋하고 자주 병합할수록 충돌이 작고 풀기 쉽습니다.
    5. 
      
  5. 적용main에서 5줄(반올림), fix-empty에서 7줄(빈 리스트로 시험)만 고르고 병합해 보세요. 그다음 양쪽 모두 5줄을 고르고 병합하면 무엇이 달라지나요? 충돌을 세 가지 방법으로 풀어 결과를 비교하고, main의 1줄과 fix-empty의 2줄처럼 붙어 있는 두 줄을 각각 고치면 어떻게 되는지도 확인하세요.
    6. 
      
  6. 판단충돌이 없다고 병합 결과가 옳다는 보장은 없습니다. 두 사람이 서로 다른 줄을 고쳤어도, 합쳐진 코드가 함께 동작하지 않을 수 있습니다. 예를 들어 5줄 충돌을 ‘main 쪽 선택’으로 풀면, 충돌 없이 들어온 fix-empty의 7줄 print(average([]))는 실행하자마자 ZeroDivisionError를 냅니다. 그래서 병합한 뒤에는 반드시 테스트를 다시 돌립니다. ‘한쪽 선택’으로 충돌을 지우면 다른 사람의 수정이 조용히 사라질 수 있으니, 두 변경의 의도를 확인하고 합쳐야 합니다.
    7.
