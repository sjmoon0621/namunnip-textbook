스택과 큐는 어디에 쓰이고, 무엇으로 구현할까?

읽기 · 추상 자료형 · 연산 비용 · deque

스택과 큐는 “넣고 꺼내는 순서”만 정한 규칙입니다. 규칙은 같아도 구현에 따라 속도와 메모리가 달라집니다. 실제 프로그램에서는 무엇을 골라 써야 할까요?

1순서 규칙이 쓰이는 곳

스택 (후입선출)큐 (선입선출)
규칙가장 최근 것을 먼저 처리가장 오래 기다린 것을 먼저 처리
예함수 호출 스택, 실행 취소(Ctrl+Z), 브라우저 뒤로 가기, 괄호 짝 검사, 수식 계산, 미로의 되돌아가기프린터 대기열, 키보드 입력 버퍼, 운영체제의 작업 대기열, 메시지 처리, 가까운 곳부터 넓혀 가는 탐색(너비 우선 탐색)
핵심 연산push, pop, peek(맨 위 보기), is_emptyenqueue, dequeue, peek(맨 앞 보기), is_empty

이처럼 연산의 이름과 뜻만 정하고 내부 구현은 감춘 자료 구조를 추상 자료형이라 합니다. 쓰는 쪽은 연산만 알면 되고, 구현은 더 빠른 것으로 바꿔도 프로그램의 나머지는 고칠 필요가 없습니다.

2구현에 따른 연산 비용

n은 들어 있는 원소 수입니다. ‘한 번’은 원소 수와 관계없이 거의 일정한 시간, ‘n에 비례’는 원소가 많을수록 오래 걸린다는 뜻입니다.

구현뒤에 넣기뒤에서 꺼내기앞에서 꺼내기i번째 보기
파이썬 list한 번 (평균)한 번n에 비례한 번
원형 배열한 번 (가득 차면 불가)한 번한 번한 번
연결 리스트한 번 (tail 유지)단일 연결이면 n에 비례한 번n에 비례
collections.deque한 번한 번한 번양 끝은 빠르고 가운데는 느림

list의 append가 ‘평균’ 한 번인 까닭은, 미리 잡아 둔 칸이 다 차면 더 큰 공간을 잡아 전체를 옮기기 때문입니다. 이 일은 가끔만 일어나서 평균을 내면 한 번 정도의 비용이 됩니다.

3문제를 풀 때는 라이브러리로

stack = []                   # 스택: 리스트 그대로
stack.append('a'); stack.append('b')
stack.pop()                  # 'b'

from collections import deque
q = deque()                  # 큐: deque
q.append('a'); q.append('b')
q.popleft()                  # 'a'
len(q) == 0                  # 비었는지 확인 (또는 not q)

원리를 익힐 때는 리스트로 직접 만들어 보고, 실제 문제를 풀 때는 이렇게 검증된 라이브러리를 씁니다. queue.Queue도 있지만, 이것은 여러 스레드가 함께 쓰도록 잠금 장치를 더한 것이라 한 프로그램 안의 일반적인 큐로는 deque가 알맞습니다.

판단“연결 리스트가 배열보다 항상 빠르다”는 틀린 말입니다. 연결 리스트는 앞에서 넣고 빼기가 빠른 대신, i번째 원소를 찾으려면 head부터 따라가야 하고 노드마다 참조를 저장할 메모리가 더 듭니다. 어떤 연산을 자주 하는지에 따라 알맞은 구현이 달라집니다.
