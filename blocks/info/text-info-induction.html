문제 속에서 재귀 관계를 어떻게 찾을까?

읽기 · 재귀 관계 · 귀납 가정 · 반복문을 재귀로 바꾸기

재귀 함수는 짧고 읽기 쉽지만, 처음 보는 문제에서 “자기 자신을 어떻게 부르지?”를 떠올리기는 어렵습니다. 재귀 관계를 찾는 데 쓸 수 있는 질문이 있을까요?

1세 가지 질문

  • 쪼개기: 이 문제를 모양은 같고 크기만 더 작은 문제로 바꿀 수 있는가? (n → n − 1, 리스트 → 첫 원소를 뺀 리스트, n → n // 2)
  • 조합하기: 작은 문제의 답을 이미 안다고 가정하면, 그것으로 지금 문제의 답을 어떻게 만드는가?
  • 멈추기: 더 쪼갤 수 없는 가장 작은 문제는 무엇이고, 그 답은 바로 알 수 있는가?

두 번째 질문의 “이미 안다고 가정”이 수학적 귀납법의 귀납 가정입니다. 귀납법에서 “n − 1일 때 성립한다고 가정하면 n일 때도 성립한다”를 보이듯, 재귀 함수에서는 “재귀 호출이 작은 문제를 맞게 풀어 준다고 믿으면 이 함수도 맞다”를 보이면 됩니다. 호출이 몇 단계로 이어지는지 머릿속으로 따라갈 필요가 없습니다.

문제재귀 관계 (조합하기)기저 조건 (멈추기)
거듭제곱 aⁿpower(a, n) = a * power(a, n - 1)n == 0 → 1
리스트 최댓값max(xs[0], biggest(xs[1:]))원소가 1개 → 그 원소
회문 판별s[0] == s[-1] and is_pal(s[1:-1])길이 0 또는 1 → True
최대공약수gcd(a, b) = gcd(b, a % b) (유클리드 호제법)b == 0 → a
하노이 탑 n개위의 n − 1개를 보조 기둥으로 → 가장 큰 원판을 목표 기둥으로 → n − 1개를 목표 기둥으로. 이동 횟수 T(n) = 2T(n − 1) + 1n == 0 → 옮길 것 없음 (T(0) = 0)

하노이 탑은 재귀 관계가 특히 잘 드러나는 예입니다. 원판 n개를 옮기는 방법을 직접 떠올리기는 어렵지만, “n − 1개를 옮기는 방법은 이미 안다”고 가정하면 세 단계로 끝납니다. 관계식을 풀면 T(n) = 2ⁿ − 1이므로, 원판 20개면 1,048,575번을 옮겨야 합니다.

2회문 판별을 귀납 가정으로 읽기

def is_pal(s):
    if len(s) <= 1:                          # 기저 조건: 빈 문자열과 한 글자는 회문
        return True
    return s[0] == s[-1] and is_pal(s[1:-1])  # 양 끝이 같고, 가운데가 회문이면 회문

is_pal(s[1:-1])이 가운데 부분을 옳게 판정한다고 믿으면, 양 끝 글자가 같은지만 더 확인하면 됩니다. 인자의 길이가 매번 2씩 줄어 언젠가 1 이하가 되므로 반드시 기저 조건에 닿습니다. 옳게 조합한다와 반드시 끝난다, 두 가지를 확인하면 재귀 함수가 옳다고 말할 수 있습니다.

3재귀 관계가 보이지 않을 때: 반복문을 재귀로 바꾸기

관계가 바로 보이지 않으면, 먼저 반복문으로 풀고 그것을 재귀로 옮겨 보는 것도 좋은 연습입니다. 1부터 n까지의 합을 예로 들어 봅니다.

반복

def total_loop(n):
    s = 0
    for i in range(1, n + 1):
        s = s + i
    return s

재귀

def total_rec(n):
    if n == 0:
        return 0
    return n + total_rec(n - 1)
  • 반복이 끝나는 조건(더 더할 수가 없음)이 기저 조건이 됩니다.
  • 한 바퀴에 하는 일(i를 더함)이 조합이 되고, 남은 반복은 재귀 호출이 맡습니다.
  • 반복문에서 바뀌던 변수(i)는 재귀 함수의 매개변수가 됩니다.

누적 변수 s를 매개변수로 넘기는 방법도 있습니다. def total_acc(n, s=0):에서 n == 0이면 s를 돌려주고, 아니면 total_acc(n - 1, s + n)을 돌려줍니다. 반복문의 s를 그대로 옮긴 모양이라 변환하기 쉽습니다.

판단재귀 관계가 맞아도 효율은 따로 따져야 합니다. xs[1:]와 s[1:-1] 같은 슬라이싱은 호출할 때마다 새 리스트·문자열을 복사하므로, 길이 n이면 복사에만 n²에 비례하는 시간이 듭니다. 시작 위치를 매개변수로 넘기면(biggest(xs, i)) 복사를 피할 수 있습니다. 같은 작은 문제를 여러 번 푸는 재귀는 더 큰 문제가 되는데, 이것은 다음 절에서 다룹니다.
