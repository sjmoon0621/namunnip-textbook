호출 수는 코드대로 센 정확한 값입니다(단순 재귀 2·fib(n+1) − 1, 메모 재귀 2n − 1). 트리는 단순 재귀 n ≤ 7, 메모 재귀 n ≤ 12에서만 그립니다. 점선 원은 memo에서 꺼낸 호출입니다.

      

    

    
    
      
  1. 질문피보나치 수 fib(n) = fib(n − 1) + fib(n − 2)를 정의 그대로 재귀 함수로 쓰면, n = 35쯤에서 파이썬이 몇 초씩 걸립니다. 같은 정의를 반복문으로 쓰면 n = 10000도 순식간입니다. 무엇이 이런 차이를 만들까요?
    2. 
      
  2. 복원재귀 함수는 기저 조건(fib(0) = 0, fib(1) = 1)과 재귀 관계로 이루어집니다. 호출마다 프레임이 하나씩 스택에 쌓였다가 반환하면 빠집니다.
    3. 
      
  3. 설명단순 재귀의 호출 트리를 보면 fib(3), fib(2) 같은 같은 부분 문제가 여러 가지에서 되풀이해 계산됩니다. 호출 수는 2·fib(n + 1) − 1로, n이 1 늘 때마다 약 1.6배씩 늘어납니다(지수적 증가). 메모 재귀는 한 번 구한 값을 딕셔너리에 저장해 두고 다시 쓰므로 호출이 2n − 1번으로 줄어듭니다. 반복은 fib(0), fib(1)에서 시작해 두 변수만 들고 n번 앞으로 나아갑니다. 스택 깊이는 두 재귀 방식이 모두 n이고, 반복은 프레임 하나로 충분합니다.
    4. 
      
  4. 연결재귀는 큰 문제를 위에서 아래로 쪼개는 설계라 정의를 그대로 옮기기 쉽고, 반복은 작은 답에서 큰 답을 아래에서 위로 쌓는 설계라 상태 변수를 직접 관리해야 합니다. 같은 계산을 되풀이하지 않는다면 두 방식의 걸음 수는 비슷하고, 차이는 호출 비용과 스택 메모리에서 생깁니다. 값을 저장해 다시 쓰는 생각은 뒤에서 배울 동적 계획법의 바탕입니다.
    5. 
      
  5. 적용단순 재귀에서 n = 5로 두고 끝까지 실행하세요. ‘같은 부분 문제 표시’를 켠 채 단계를 넘기며, fib(3)과 fib(2)가 각각 몇 번 계산되는지 세어 보세요. 메모 재귀로 바꾸면 몇 번으로 줄어드나요? n을 20, 25, 30으로 늘리며 세 방식의 호출 수를 기록하고, 단순 재귀의 호출 수가 n이 5 늘 때 몇 배가 되는지 구하세요.
    6. 
      
  6. 판단“재귀는 반복보다 항상 느리다”는 틀린 일반화입니다. 이 카드의 느림은 재귀 자체가 아니라 중복 계산 때문이고, 메모 재귀는 반복과 같은 차수의 시간이 걸립니다. 다만 파이썬은 재귀 깊이를 기본 1000으로 제한하고(sys.getrecursionlimit()), 꼬리 재귀를 반복으로 바꿔 주는 최적화도 하지 않습니다. 그래서 메모 재귀로 fib(5000)을 처음 부르면 RecursionError가 납니다. 한도를 sys.setrecursionlimit로 크게 올리면 실제 스택 메모리가 넘쳐 프로그램이 비정상 종료될 수 있습니다.
