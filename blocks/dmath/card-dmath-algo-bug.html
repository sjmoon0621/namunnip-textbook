이 알고리즘은 어떤 입력에서 틀릴까?

알고리즘의 정확성 · 오류 찾기

처음 틀린 줄을 누르세요. 틀린 곳이 없으면 마지막 줄을 누르세요.

목표는 수 목록 x₁, …, xₙ에서 가장 큰 값을 출력한다.

  1. 입력은 수 목록 x₁, …, xₙ (n ≥ 1)입력 조건을 밝혔습니다.
  2. 최댓값 m ← 0여기가 틀렸습니다. 모든 수가 음수(예: −5, −2, −9)이면 0을 출력합니다. m ← x₁로 시작해야 합니다.
  3. i = 1부터 n까지 되풀이하며, xᵢ > m이면 m ← xᵢ비교와 갱신 자체는 맞습니다.
  4. m을 출력한다.앞의 초깃값 문제를 이어받습니다.
  5. 틀린 곳이 없다.음수만 있는 목록을 넣어 보세요.

목표는 1 + 2 + ⋯ + n을 출력한다.

  1. 입력은 자연수 n입력은 분명합니다.
  2. s ← 0, i ← 1초깃값은 맞습니다.
  3. i < n인 동안 s ← s + i, i ← i + 1을 되풀이여기가 틀렸습니다. i = n일 때 반복이 멈춰 n을 더하지 않습니다. n = 3이면 6이 나와야 하는데 1 + 2 = 3이 나옵니다. 조건은 i ≤ n이어야 합니다(경계 오류).
  4. s를 출력한다.앞 줄의 경계 오류를 이어받습니다.
  5. 틀린 곳이 없다.n = 1을 넣어 보세요.

목표는 크기순으로 정렬된 목록 x₁ ≤ ⋯ ≤ xₙ에서 값 t의 위치를 찾는다(이진 탐색).

  1. lo ← 1, hi ← n탐색 범위를 전체로 정했습니다.
  2. lo ≤ hi인 동안 mid ← ⌊(lo + hi)/2⌋가운데를 고르는 것은 맞습니다.
  3. 만약 x_mid = t이면 mid를 출력하고 끝낸다.찾으면 끝냅니다.
  4. x_mid < t이면 lo ← mid, 아니면 hi ← mid여기가 틀렸습니다. lo = mid로 두면 범위가 줄지 않을 수 있습니다. 예: lo = 1, hi = 2, t가 x₂보다 크면 mid = 1이 계속되어 끝나지 않습니다. lo ← mid + 1, hi ← mid − 1이어야 합니다.
  5. 틀린 곳이 없다.원소가 두 개인 목록에서 없는 값을 찾아보세요.

목표는 자연수 n이 소수인지 판정한다.

  1. 입력은 자연수 n ≥ 21은 소수가 아니므로 입력에서 뺐습니다.
  2. d = 2부터 d × d ≤ n인 동안 d를 1씩 늘리며:√n까지만 보면 됩니다. n = ab이면 a, b 중 하나는 √n 이하이기 때문입니다.
  3. 만약 n을 d로 나눈 나머지가 0이면 "소수 아님"을 출력하고 끝낸다.약수를 찾으면 바로 끝냅니다.
  4. 반복이 끝나면 "소수"를 출력한다.√n까지 약수가 없으면 소수입니다.
  5. 틀린 곳이 없다.맞습니다. n = 2, 3이면 반복을 한 번도 하지 않고 "소수"를 출력하고, n = 4이면 d = 2에서 걸러집니다. 경계까지 확인했습니다.

  1. 질문알고리즘이 예시 몇 개에서 맞는 답을 냈다고 늘 맞을까? 어떤 입력을 넣어 봐야 숨은 오류가 드러날까?
  2. 복원알고리즘은 입력과 출력이 분명하고, 단계가 모호하지 않으며, 유한 번 만에 끝나야 한다.
  3. 설명자주 나오는 오류는 ① 초깃값(최댓값을 0으로 시작), ② 경계 오류(<와 ≤, 한 번 덜 또는 더 반복), ③ 끝나지 않는 반복(범위가 줄지 않음)이다. 이런 오류는 경계와 극단의 입력(n = 1, 빈 목록, 모두 음수, 원소 두 개)에서 잘 드러난다. 알고리즘이 맞다는 것은 몇 개의 예가 아니라 모든 입력에 대한 논증(반복할 때마다 지켜지는 성질, 매번 줄어드는 양)으로 보인다.
  4. 연결대수 과목에서 배운 수학적 귀납법과 같은 생각이다. "반복 전에 성립하고, 한 번 반복해도 유지되는 성질"을 찾으면 알고리즘이 끝났을 때의 결과가 맞음을 증명할 수 있다.
  5. 적용네 알고리즘에서 처음 틀린 줄을 찾자. 틀린 알고리즘마다 틀린 답을 내는 입력을 하나씩 직접 만들어 보자.
  6. 판단테스트를 많이 통과해도 오류가 없다는 보장은 없다. 반대로 반례 하나면 틀렸다는 것은 확실하다. 확인할 때는 평범한 입력보다 경계의 입력을 먼저 넣어 보자.
