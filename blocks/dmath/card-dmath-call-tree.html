재귀로 피보나치 수를 구하면 왜 이렇게 느릴까?

재귀적 알고리즘 · 조작

  1. 질문"\(F(n) = F(n - 1) + F(n - 2)\), \(F(1) = F(2) = 1\)"을 그대로 컴퓨터 함수로 쓰면 아주 짧은 프로그램이 된다. 그런데 \(F(40)\)만 넣어도 한참 걸린다. 무엇이 문제일까?
  2. 복원수열의 귀납적 정의는 앞의 항으로 다음 항을 정한다.
  3. 설명자기 자신을 더 작은 입력으로 다시 부르는 알고리즘을 재귀적 알고리즘이라 한다. 재귀에는 ① 더 이상 부르지 않는 기저 경우(\(F(1), F(2)\))와 ② 문제를 줄이는 재귀 단계가 있어야 한다. 피보나치를 그대로 재귀로 쓰면 \(F(n - 2)\)를 두 번, \(F(n - 3)\)을 세 번…처럼 같은 계산을 거듭해, 호출 횟수 \(c_n = c_{n-1} + c_{n-2} + 1\)이 \(F(n)\)처럼 기하급수로 늘어난다. 한 번 구한 값을 기억해 두면(메모이제이션) 각 값을 한 번씩만 계산한다.
  4. 연결하노이의 탑, 다음 카드의 빠른 거듭제곱, 병합 정렬처럼 재귀가 잘 맞는 문제도 많다. 호출 횟수를 점화식으로 세우는 것이 알고리즘의 효율을 따지는 기본 방법이다.
  5. 적용\(n\)을 늘리며 호출 나무가 얼마나 빨리 커지는지 보자. 같은 색 마디가 몇 번 나오는가? "기억하기"를 켜면 나무가 어떻게 바뀌는가? 아래에서 \(n = 30, 40\)일 때 호출 횟수를 비교해 보자.
  6. 판단기저 경우가 없거나 입력이 줄지 않으면 재귀는 끝나지 않는다. 또 짧고 아름다운 코드가 빠른 코드는 아니다. 정의를 그대로 옮기기 전에 같은 계산이 반복되는지 따져 보자.
