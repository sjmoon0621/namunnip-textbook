1.4.1

끝없이 더한 값은 어떻게 정할까?

  1. 질문1/2 + 1/6 + 1/12 + 1/20 + …처럼 끝없이 이어지는 덧셈은 끝까지 더할 수 없습니다. 그렇다면 이 덧셈의 '값'은 무엇으로 정해야 할까요?
  2. 복원수열의 합 ∑k=1n ak는 유한 개를 더한 값입니다. 1/{k(k + 1)} = 1/k − 1/(k + 1)처럼 분수를 두 분수의 차로 나누면, 이웃한 항이 지워지며 합이 간단해집니다.
  3. 설명수열 {an}의 각 항을 차례로 덧셈 기호로 이은 식 a1 + a2 + a3 + … 을 급수라 하고 ∑n=1∞ an으로 씁니다. 첫째항부터 제n항까지의 합 Sn = a1 + … + an을 부분합이라 합니다. 부분합의 수열 {Sn}이 S에 수렴하면 급수는 수렴한다고 하고, S를 급수의 합이라 합니다. 이때 ∑n=1∞ an = S로 씁니다. {Sn}이 발산하면 급수도 발산합니다. 곧 급수의 합은 '끝까지 더한 값'이 아니라 부분합의 극한입니다.
  4. 연결수렴하는 두 급수 ∑an = S, ∑bn = T에 대해 ∑kan = kS, ∑(an ± bn) = S ± T가 성립합니다. 부분합에 수열의 극한에 대한 성질을 쓴 결과입니다. 부분합을 식으로 구하기 어려운 급수는 다음 카드처럼 일반항을 먼저 살펴봅니다.
  5. 적용'한 항 더하기'를 눌러 첫 번째 급수의 부분합을 쌓아 보세요. 막대(더한 항)는 점점 짧아지고 초록 점(부분합)은 1에 다가갑니다. 아래 식에서 지워지지 않고 남는 항은 무엇인가요? 두 번째 급수에서는 왜 두 항(1과 1/2)이 남나요? 세 번째 급수는 더하는 항이 0에 가까워지는데도 부분합이 √(n + 1) − 1로 끝없이 커집니다. 네 번째 급수의 부분합은 1과 0을 오갑니다.
  6. 판단1 − 1 + 1 − 1 + … 을 (1 − 1) + (1 − 1) + … 으로 묶어 0이라고 하거나, 1 + (−1 + 1) + … 로 묶어 1이라고 하면 안 됩니다. 괄호를 마음대로 넣으면 다른 급수가 됩니다. 급수의 수렴·발산은 반드시 부분합의 수열로 판정합니다. 또 소거할 때 앞에서 남는 항과 뒤에서 남는 항의 개수가 같은지 확인해야 합니다.

1.4.2

더하는 항이 0으로 가면 급수는 수렴할까?

부분합은 첫째항부터 106번째 항까지 실제로 더해 계산했습니다. Sₙ − S(n/10)은 n/10번째 항 다음부터 n번째 항까지 더한 양입니다.

  1. 질문1 + 1/2 + 1/3 + 1/4 + …에서 더하는 항은 0에 한없이 가까워집니다. 더하는 양이 거의 0이면 부분합은 어떤 값에서 멈출까요?
  2. 복원급수가 수렴한다는 것은 부분합의 수열 {Sn}이 수렴한다는 뜻입니다. 또 Sn − Sn−1 = an(n ≥ 2)입니다.
  3. 설명급수 ∑an이 S에 수렴하면 lim Sn = lim Sn−1 = S이므로 lim an = lim (Sn − Sn−1) = S − S = 0입니다. 곧 급수가 수렴하면 lim an = 0입니다. 이 명제의 대우를 쓰면 판정법이 됩니다. lim an ≠ 0이면(또는 수렴하지 않으면) 급수는 발산합니다. 그러나 거꾸로 lim an = 0이라고 급수가 수렴하는 것은 아닙니다. ∑ 1/n이 그 예입니다. 항을 1/2, 1/3 + 1/4, 1/5 + … + 1/8, … 처럼 2배 길이로 묶으면 묶음마다 1/2 이상이므로, 부분합은 1/2씩 끝없이 쌓입니다.
  4. 연결lim an = 0은 급수가 수렴하기 위한 필요조건일 뿐 충분조건이 아닙니다. 그래서 일반항이 0으로 가는 급수는 부분합을 직접 구하거나, 다음 절의 등비급수처럼 부분합의 식을 아는 꼴로 바꾸어 판정합니다.
  5. 적용∑ 1/n에서 n을 10배씩 늘리며 Sn − S(n/10)을 보세요. 10배 구간마다 늘어나는 양은 거의 일정합니다(약 2.3). 이 양이 줄지 않는다면 부분합은 어디로 가나요? ∑ 1/n2에서는 같은 양이 어떻게 변하나요? ∑ n/(n + 1)은 an만 보고도 판정할 수 있습니다.
  6. 판단"lim an = 0이므로 ∑an은 수렴한다"는 흔한 잘못입니다. 일반항의 극한은 발산을 판정할 때만 결론을 줍니다. 또 ∑ 1/n의 부분합은 106항을 더해도 약 14.39에 불과해서, 화면만 보면 수렴하는 것처럼 보일 수 있습니다. 그래서 판정은 묶어서 비교하는 것처럼 식으로 해야 합니다.
