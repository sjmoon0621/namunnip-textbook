먼저 알아야 할 것조건문과 나머지 연산(정보), 확률과 여사건(수학), 코드 검토(오픈소스로 협력 개발).

4.4.1버그는 경계에 숨는다

프로그램의 버그는 대개 평범한 입력이 아니라 조건이 바뀌는 경계에서 생긴다. 윤년 함수의 경계는 4의 배수, 100의 배수, 400의 배수이다. 리스트를 다루는 함수의 경계는 빈 리스트, 원소가 하나인 리스트, 첫 원소와 마지막 원소이다. 점수에 따라 등급을 매기는 함수라면 90점이 A인지 B인지 같은 구간의 끝점이 경계이다. 그래서 시험할 입력은 무작위로 고르기보다, 조건을 하나하나 살펴 경계와 그 바로 옆의 값을 일부러 고른다. 이것이 경계값 시험이다.

정리 4.4.1 무작위 시험으로 버그를 찾을 확률

입력 가운데 비율 \(f\)에서만 틀리는 버그가 있을 때, 무작위 입력 \(n\)개로 시험해 하나라도 틀린 입력을 만날 확률은 \[1 - (1 - f)^n\]이다. \(f\)가 작은 버그는 시험을 아주 많이 해야 드러난다. 그런 버그는 대개 경계에 모여 있으므로, 경계값을 직접 고르면 시험 몇 개로 찾는다.

그림 1에서 시험 수를 바꾸어 보자. 틀린 연도는 1만 년 가운데 75개, 곧 0.75%이다. 무작위 연도 100개로 시험하면 버그를 찾을 확률이 약 53%로 동전 던지기와 비슷하다. 300개를 시험해도 약 90%이다. 그런데 경계값인 1900을 하나만 넣으면 함수가 '윤년'이라 답해 틀린 것이 바로 드러난다. 2000(400의 배수, 윤년)과 2100(평년)을 함께 넣으면 고친 함수가 맞는지도 확인할 수 있다.1

4.4.2디버깅

시험에서 틀린 결과가 나오면 그 원인을 찾아 고치는 디버깅을 한다. 먼저 틀린 결과를 늘 되풀이해 낼 수 있는 가장 작은 입력을 찾는다. 그다음 그 입력으로 프로그램을 따라가며, 변수의 값이 예상과 처음 달라지는 곳을 찾는다. 중간중간 값을 출력해 보거나, 디버거로 한 줄씩 실행하며 변수를 살핀다. 의심되는 범위를 반씩 좁혀 가면 긴 코드에서도 빠르게 찾는다. 원인을 고친 뒤에는 그 입력을 시험 목록에 영원히 남겨, 같은 버그가 다시 생기지 않는지 확인한다. 이것을 회귀 시험이라 한다.

4.4.3예제 하나를 끝까지

예제 4.4.2

0.75%의 입력에서만 틀리는 버그를 무작위 시험으로 95% 넘는 확률로 찾으려면 시험이 몇 개 필요한가? 윤년 규칙의 조건을 모두 확인하는 경계값 시험은 몇 개면 충분한지 정하고, 고친 함수 y % 4 == 0 and (y % 100 != 0 or y % 400 == 0)를 그 시험으로 확인하여라.

\(1 - 0.9925^n > 0.95\)에서 \(0.9925^n < 0.05\)이고, 양변에 로그를 취하면 \(n > \dfrac{\ln 0.05}{\ln 0.9925} \approx \dfrac{-3.00}{-0.00753} \approx 398\)이다. 무작위 시험이 약 400개 필요하다.

경계값 시험은 규칙의 네 경우에서 하나씩, 곧 4의 배수가 아닌 해(2023), 4의 배수이지만 100의 배수가 아닌 해(2024), 100의 배수이지만 400의 배수가 아닌 해(1900), 400의 배수(2000)의 네 개면 된다. 고친 함수는 2023에 거짓, 2024에 참, 1900에 \(100\)으로 나누어떨어지고 400으로 나누어떨어지지 않아 거짓, 2000에 참을 돌려주어 네 시험을 모두 통과한다. 즉 시험 네 개가 무작위 시험 400개보다 확실하다. 그래서 시험은 많이 하는 것보다 조건의 경계를 빠짐없이 고르는 것이 중요하다.

1테스트를 코드로 남기기

          
테스트를 손으로 매번 입력하면 귀찮아서 결국 덜 하게 된다. 파이썬 표준 라이브러리의 unittest로 테스트를 파일에 적어 두면, 명령 한 줄로 언제든 모두 다시 돌릴 수 있다.

          
import unittest
      from stats import median

      class TestMedian(unittest.TestCase):
          def test_odd(self):
              self.assertEqual(median([3, 1, 2]), 2)

          def test_even(self):                        # 경계: 짝수 개
              self.assertEqual(median([4, 1, 3, 2]), 2.5)

          def test_empty(self):                       # 예외 경우
              with self.assertRaises(ValueError):
                  median([])

      if __name__ == "__main__":
          unittest.main()

          
실행하면 통과한 테스트는 점(.)으로, 실패한 테스트는 F, 예상하지 못한 오류는 E로 표시되고, 실패한 테스트마다 기대값과 실제 값을 보여 준다. 버그를 고칠 때마다 이 파일을 다시 돌리면 회귀 테스트가 된다. 실무에서는 pytest처럼 더 간결하게 쓰는 외부 라이브러리도 많이 쓴다.

          
2디버깅의 순서

          
재현

          
버그가 언제나 나타나는 가장 작은 입력을 찾는다. 그 입력을 그대로 테스트로 만들어 둔다.

          
범위 좁히기

          
중간 값을 print로 찍거나, 개발 환경의 디버거로 중단점(breakpoint)을 걸고 한 줄씩 실행하며 변수를 본다. 값이 처음으로 예상과 달라지는 줄 근처에 원인이 있다. 코드의 절반씩을 확인해 나가면 이진 탐색처럼 빠르게 좁혀진다.

          
원인 이해

          
증상(틀린 출력)이 아니라 원인(잘못된 조건, 경계 처리, 자료형)을 찾는다. 왜 틀렸는지 설명할 수 있어야 제대로 고친 것이다.

          
수정과 확인

          
고친 뒤 재현 테스트가 통과하는지, 기존 테스트도 모두 통과하는지 확인한다.
