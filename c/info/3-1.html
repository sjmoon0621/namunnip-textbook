  2. 복원재귀 함수는 같은 모양의 더 작은 문제를 스스로 호출하고, 더 쪼갤 수 없는 기저 사례에서 멈춥니다. 트리는 뿌리에서 갈라져 내려가는 구조이고, 깊이 우선으로 훑을 수 있습니다.
    3. 
            
  3. 설명문제를 상태로 나타내면 탐색할 수 있습니다. 여기서 상태는 "i번째 물건까지 정했고, 지금까지 무게 w, 가치 v"입니다. 처음 상태는 (0, 0, 0)이고, 한 번의 결정(넣는다/안 넣는다)이 상태를 다음 상태로 바꿉니다. 가능한 상태를 모두 모은 것이 상태 공간이고, 결정을 가지로 그리면 상태 공간 트리가 됩니다. 완전 탐색은 이 트리의 모든 잎을 확인해 가장 좋은 것을 고릅니다. 모든 경우를 보므로 답이 틀릴 수 없습니다.
    4. 
            
  4. 연결물건마다 선택지가 2개이므로 잎은 2ⁿ개, 노드는 2ⁿ⁺¹ − 1개입니다. n = 20이면 잎이 1,048,576개, n = 30이면 약 10억 개, n = 40이면 약 1조 개입니다. 순서를 정하는 문제(예: 도시 n곳을 도는 순서)는 상태 수가 n!로, 2ⁿ보다도 빨리 커집니다(10! = 3,628,800).
    5. 
            
  5. 적용n = 4, cap = 10에서 끝까지 실행해 최고 가치와 그 조합을 확인하세요. 잎 몇 개가 무게를 넘었나요? cap을 바꿔도 방문하는 노드 수는 달라지나요? n을 하나 늘릴 때마다 노드 수는 몇 배가 되나요?
    6. 
            
  6. 판단완전 탐색은 "느리고 쓸모없는 방법"이 아닙니다. 경우가 적으면 가장 확실하고 빨리 짤 수 있는 방법이고, 더 똑똑한 알고리즘의 답이 맞는지 검사하는 기준으로도 씁니다. 다만 상태 수가 지수적으로 늘기 때문에 n이 조금만 커져도 끝나지 않습니다. 이 카드의 탐색은 무게가 이미 넘은 상태에서도 계속 내려갑니다. 이런 쓸데없는 가지를 잘라 내는 방법은 가지치기에서 다룹니다.
