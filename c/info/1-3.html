  2. 복원재귀 함수는 기저 조건(fib(0) = 0, fib(1) = 1)과 재귀 관계로 이루어집니다. 호출마다 프레임이 하나씩 스택에 쌓였다가 반환하면 빠집니다.

  3. 설명단순 재귀의 호출 트리를 보면 fib(3), fib(2) 같은 같은 부분 문제가 여러 가지에서 되풀이해 계산됩니다. 호출 수는 2·fib(n + 1) − 1로, n이 1 늘 때마다 약 1.6배씩 늘어납니다(지수적 증가). 메모 재귀는 한 번 구한 값을 딕셔너리에 저장해 두고 다시 쓰므로 호출이 2n − 1번으로 줄어듭니다. 반복은 fib(0), fib(1)에서 시작해 두 변수만 들고 n번 앞으로 나아갑니다. 스택 깊이는 두 재귀 방식이 모두 n이고, 반복은 프레임 하나로 충분합니다.
    4. 
            
  4. 연결재귀는 큰 문제를 위에서 아래로 쪼개는 설계라 정의를 그대로 옮기기 쉽고, 반복은 작은 답에서 큰 답을 아래에서 위로 쌓는 설계라 상태 변수를 직접 관리해야 합니다. 같은 계산을 되풀이하지 않는다면 두 방식의 걸음 수는 비슷하고, 차이는 호출 비용과 스택 메모리에서 생깁니다. 값을 저장해 다시 쓰는 생각은 뒤에서 배울 동적 계획법의 바탕입니다.

          1.3.2
반복과 재귀, 어떤 문제에 어느 쪽이 맞을까?
읽기 · 반복구조와 재귀구조의 비교 · 명시적 스택 · 재귀 한도
        

        

          
반복으로 풀 수 있는 문제는 재귀로도 풀 수 있고, 그 반대도 마찬가지입니다. 그렇다면 둘 중 무엇을 고를지는 취향의 문제일까요?


          
1두 방식은 생각하는 방향이 다릅니다

          
반복구조는 “지금 상태에서 한 걸음 나아가려면 무엇을 바꾸는가”를 묻습니다. 변수(합계, 인덱스, 앞의 두 항 등)를 직접 두고, 반복할 때마다 고쳐 나갑니다. 재귀구조는 “이 문제를 같은 모양의 더 작은 문제로 바꾸면 무엇이 남는가”를 묻습니다. 상태는 각 호출의 매개변수와 지역 변수에 나뉘어 담기고, 언어가 호출 스택으로 관리해 줍니다.

          

            
반복구조재귀구조

            
              
설계작은 답에서 큰 답으로 쌓아 올림(상향식)큰 문제를 작은 문제로 쪼갬(하향식)

              
상태 관리변수를 프로그래머가 직접 갱신호출마다 프레임이 따로 보관

              
추가 메모리대개 변수 몇 개스택 깊이만큼의 프레임

              
실행 비용반복 한 번은 가벼움호출 한 번마다 프레임을 만들고 지우는 비용

              
잘 맞는 문제차례로 훑기, 누적, 정해진 횟수의 갱신트리·폴더처럼 구조가 중첩된 자료, 분할 정복, 백트래킹

              
흔한 실수경계값(off-by-one), 갱신 순서기저 조건 누락, 중복 계산, 깊이 초과

            
          


          
2구조가 중첩되면 재귀가 자연스럽습니다

          
[1, [2, 3], [[4]], 5]처럼 리스트 안에 리스트가 몇 겹으로 들어 있는지 모를 때, 안의 정수를 모두 더해 봅니다.

          

            
재귀
def deep_sum(x):
          if isinstance(x, int):
              return x
          total = 0
          for y in x:
              total += deep_sum(y)
          return total

            
반복 + 직접 만든 스택
def deep_sum_loop(x):
          total, stack = 0, [x]
          while stack:
              y = stack.pop()
              if isinstance(y, int):
                  total += y
              else:
                  stack.extend(y)
          return total

          

          
두 함수 모두 15를 돌려줍니다. 재귀 쪽은 “원소가 정수면 그 값, 리스트면 각 원소의 합”이라는 정의를 그대로 옮겼습니다. 반복 쪽은 앞으로 처리할 것을 담는 스택을 직접 만들었습니다. 재귀 함수가 호출 스택에 맡기던 일을 손으로 하는 것입니다. 이처럼 어떤 재귀든 명시적 스택을 쓰면 반복으로 바꿀 수 있지만, 코드가 길어지고 의도가 덜 드러날 수 있습니다. 스택은 다음 단원에서 자세히 다룹니다.


          
3단순히 차례로 훑는 일은 반복이 낫습니다

          
1부터 n까지 더하기를 return n + total_rec(n - 1)로 쓰면 깊이가 n이 됩니다. 파이썬의 재귀 한도는 기본 1000이라(sys.getrecursionlimit()로 확인) total_rec(5000)은 RecursionError를 냅니다. 같은 일을 하는 for문은 n이 백만이어도 문제없습니다. 일부 언어는 마지막 동작이 재귀 호출뿐인 꼬리 재귀를 반복으로 바꿔 주지만, 파이썬은 이 최적화를 하지 않습니다.

          
하노이 탑은 반대 예입니다. 재귀로는 몇 줄이면 되지만, 반복으로 쓰려면 “가장 작은 원판을 한 방향으로 돌리고, 그 사이에 가능한 다른 이동을 한다” 같은 규칙을 따로 찾아내야 합니다. 이동 횟수는 두 방식 모두 2ⁿ − 1로 같고, 깊이는 n이라 한도 걱정도 없습니다.


          
판단선택의 기준은 취향이 아니라 문제의 구조와 크기입니다. 문제가 스스로 닮은 구조이고 깊이가 작으면 재귀가 읽기 쉽고 오류도 적습니다. 깊이가 입력 크기에 비례해 커지거나, 같은 부분 문제를 되풀이한다면 반복이나 메모이제이션으로 바꾸어야 합니다. 어느 쪽이든 옳은지(기저 조건·종료 조건)와 얼마나 걸리는지(호출 수·반복 수)를 따로 따져야 합니다.
