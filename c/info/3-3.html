      3. 
            
    3. 설명가장 큰 원판에 주목합니다. 이것을 A에서 C로 옮기려면 그 순간 나머지 n−1개가 모두 B에 있어야 합니다. 그러면 전체 문제는 세 부분으로 분해됩니다. ① 원판 n−1개를 A에서 B로 옮기기, ② 가장 큰 원판을 A에서 C로 옮기기, ③ 원판 n−1개를 B에서 C로 옮기기. ①과 ③은 원판 수만 하나 적고 모양이 같은 부분 문제입니다. 원판 1개는 그냥 옮기면 되는 기저 사례입니다.

          3.3.2
    큰 문제 속에서 같은 모양의 작은 문제를 어떻게 찾을까?
    읽기 · 문제 분해 · 관계식과 기저 사례
        
    
        
    
          
    "리스트에서 가장 큰 수 찾기"를 반복문 없이 풀 수 있을까요? 문제를 "앞의 n−1개에서 가장 큰 수"와 "마지막 수" 둘로 나누면, 앞쪽은 원래 문제와 똑같은 모양이고 크기만 하나 작습니다.
    

          
    1분해할 때 묻는 세 가지
    
          
      
            
    • 부분 문제: 원래 문제와 같은 모양이면서 크기가 작은 문제는 무엇인가? 크기를 무엇으로 잴지(원소 수, 원판 수, 지수 n 등) 먼저 정합니다.
      • 
            
    • 관계: 부분 문제의 답을 알고 있다면, 그것으로 전체 문제의 답을 어떻게 만드는가? 이 관계를 식으로 적은 것이 점화식(관계식)입니다.
      • 
            
    • 기저 사례: 더 쪼개지 않고 바로 답을 아는 가장 작은 경우는 무엇인가? 크기가 매번 줄어들어 반드시 여기에 닿아야 합니다.
      • 
          
    
          
    def biggest(a):
          if len(a) == 1:                  # 기저 사례
              return a[0]
          rest = biggest(a[:-1])           # 부분 문제: 앞의 n-1개
          return max(rest, a[-1])          # 관계: 부분 답과 마지막 수 비교
    

          
    2여러 문제의 분해
    
          
    
            
    전체 문제부분 문제전체와 부분의 관계기저 사례
    
            
              
    1부터 n까지의 합 S(n)S(n−1)S(n) = S(n−1) + nS(1) = 1
    
              
    리스트의 최댓값앞의 n−1개의 최댓값max(부분 답, 마지막 원소)원소 1개
    
              
    하노이 탑 (원판 n개)원판 n−1개 옮기기 (두 번)T(n) = 2T(n−1) + 1원판 1개: 한 번 옮김
    
              
    거듭제곱 aⁿa의 (n // 2)제곱짝수면 (부분 답)², 홀수면 a × (부분 답)²a⁰ = 1
    
              
    리스트 정렬앞 절반 정렬, 뒤 절반 정렬정렬된 두 리스트를 합병원소 0개나 1개
    
              
    계단을 1칸 또는 2칸씩 올라 n칸에 가는 방법 수 W(n)W(n−1), W(n−2)W(n) = W(n−1) + W(n−2)W(1) = 1, W(2) = 2
    
                
          
    
          
    표의 마지막 줄은 마지막 걸음이 1칸인지 2칸인지로 경우를 나눈 것입니다. 마지막이 1칸이면 그 전까지 n−1칸을 오르는 방법 수, 2칸이면 n−2칸을 오르는 방법 수만큼 있습니다. 관계는 "마지막 한 걸음"이나 "가장 큰 원판"처럼 마지막 결정 하나에 주목할 때 잘 보입니다.
    

          
    3관계의 세 가지 모양
    
          

          
    4부분 문제의 답을 믿기
    
          
    재귀 코드를 읽을 때 호출을 끝까지 따라가면 금방 길을 잃습니다. 대신 "biggest(a[:-1])는 앞의 n−1개의 최댓값을 정확히 돌려준다"고 믿고, 그 답으로 전체 답을 맞게 만드는지만 확인합니다. 이것은 수학적 귀납법과 같은 생각입니다. 기저 사례가 맞고, n−1에서 맞으면 n에서도 맞음을 보이면 모든 n에서 맞습니다.
    
          
    판단부분 문제가 원래 문제보다 작아지지 않으면(예: biggest(a)가 다시 biggest(a)를 부르면) 재귀는 끝나지 않고, 파이썬은 RecursionError를 냅니다. 또 같은 모양이라고 해서 아무렇게나 나눈 것이 좋은 분해는 아닙니다. 위의 최댓값 코드는 맞지만 a[:-1]이 리스트를 매번 복사하고 재귀 깊이가 n이라, 원소가 1000개 가까이 되면 파이썬 기본 재귀 한도(보통 1000)에 걸립니다. 분해는 정확성을 생각하는 도구이고, 효율은 따로 따져야 합니다.
