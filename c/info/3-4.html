반으로 나눠 정렬하면 왜 빨라질까?

분할 정복 · 합병 정렬과 퀵 정렬 · 재귀 트리

아직 정렬 안 됨정렬 끝피벗 (퀵 정렬)

입력
비교 횟수 (지금 / 전체)
—
재귀 깊이
—
선택 정렬이라면 n(n−1)/2
—
참고 n log₂n
—

              
비교 횟수는 원소 두 개의 크기를 비교한 횟수입니다. 합병 정렬은 merge 안의 비교를, 퀵 정렬은 피벗과 비교되는 원소 수(구간 길이 − 1)를 셉니다. 위 퀵 정렬 코드는 리스트를 두 번 훑으므로 실제 비교는 그 두 배이지만, 자리를 바꾸며 한 번만 훑는 구현도 있어 한 번으로 셉니다.

            

          

          
    
            
  1. 질문원소를 하나씩 보며 가장 작은 것을 골라 앞으로 보내는 선택 정렬은 원소 16개에 비교를 120번 합니다. 1000개면 약 50만 번입니다. 리스트를 반으로 나눠 각각 정렬한 뒤 합치면 비교가 줄어들까요?
    2. 
            
  2. 복원문제 분해는 전체 문제를 같은 모양의 부분 문제로 나누고, 부분 문제의 답으로 전체 답을 만드는 관계를 찾는 것입니다. 재귀 함수는 기저 사례에서 멈춥니다.
    3. 
            
  3. 설명분할 정복은 ① 문제를 작은 부분 문제로 나누고(분할), ② 각각을 재귀로 풀고(정복), ③ 그 답을 합쳐 전체 답을 만듭니다(결합). 합병 정렬은 무조건 반으로 나누고, 정렬된 두 리스트의 맨 앞끼리 비교하며 하나로 합칩니다. 나누기는 쉽고 합치기에서 일을 합니다. 퀵 정렬은 피벗을 하나 골라 그보다 작은 것과 크거나 같은 것으로 나누고, 각각 정렬해 이어 붙입니다. 나누기에서 일을 하고 합치기는 이어 붙이기뿐입니다.
    4. 
            
  4. 연결합병 정렬은 한 층마다 합병에서 많아야 n번 비교하고, 반씩 나누므로 층은 약 log₂n개입니다. 그래서 비교 횟수는 n log₂n 정도이고, 입력이 어떻게 놓여 있든 같습니다. 퀵 정렬은 피벗이 구간을 고르게 나누면 합병 정렬과 비슷하지만, 이미 정렬된 리스트에서 첫 원소를 피벗으로 고르면 한쪽이 비어 층이 n개가 되고 비교가 n(n−1)/2번으로 늘어납니다.
    5. 
            
  5. 적용n = 8, 무작위 입력에서 합병 정렬을 한 단계씩 실행하며 재귀 트리가 내려갔다 올라오는 순서를 따라가세요. 이어서 n = 16에서 세 가지 입력에 대해 두 방법의 비교 횟수와 재귀 깊이를 표로 적어 보세요. 퀵 정렬이 가장 느린 입력은 무엇이고, 그때 재귀 트리는 어떤 모양인가요?
    6. 
            
  6. 판단"나누기만 하면 빨라진다"는 틀린 생각입니다. 하노이 탑처럼 크기가 하나만 줄어드는 부분 문제가 둘이면 오히려 일이 두 배씩 늘고, 퀵 정렬도 나뉘는 비율이 나쁘면 느려집니다. 분할 정복이 빠른 것은 부분 문제의 크기가 일정한 비율로 줄고, 결합하는 비용이 작기 때문입니다. 실제 퀵 정렬은 피벗을 무작위로 고르거나 세 값의 중간값으로 골라 이런 최악을 피하며, 파이썬의 sorted()는 합병 정렬과 삽입 정렬을 섞은 Timsort를 씁니다.
    7.

반복문으로 a를 곱하기
—

                
power(n//2)를 두 번 호출
—

                
half에 저장해 한 번 호출
—

                
n의 2진수
—

              

              

              
세 칸의 숫자는 곱셈 횟수입니다. "두 번 호출"은 half를 쓰지 않고 return power(a, n // 2) * power(a, n // 2)처럼 쓴 경우입니다. 파이썬의 정수는 자릿수 제한이 없어 큰 값도 정확히 구하지만, 자릿수가 커지면 곱셈 한 번도 오래 걸립니다. 실제로는 pow(a, n) 또는 a ** n을 씁니다.

            

          

          
    
            
  1. 질문3¹⁰⁰⁰을 구하려고 3을 계속 곱하면 곱셈 999번이 필요합니다. 그런데 3¹⁰⁰⁰ = (3⁵⁰⁰)²이므로 3⁵⁰⁰만 알면 곱셈 한 번으로 끝납니다. 이렇게 계속 나누면 곱셈이 몇 번으로 줄어들까요?
    2. 
            
  2. 복원분할 정복은 문제를 작은 부분 문제로 나누고, 그 답을 결합해 전체 답을 만듭니다. 지수 법칙에 따라 a2m = (am)², a2m+1 = (am)² × a입니다.
    3. 
            
  3. 설명power(a, n)은 부분 문제 power(a, n // 2)의 답 half를 구한 뒤, n이 짝수면 half × half, 홀수면 half × half × a를 돌려줍니다. 지수가 매번 반으로 줄므로 호출은 약 log₂n번만 쌓이고, 한 층에서 곱셈은 1~2번입니다. 각 줄의 n을 2진수로 보면 한 줄 내려갈 때마다 맨 오른쪽 자리가 하나씩 떨어집니다. 그래서 곱셈을 두 번 하는 홀수 단계(주황)의 수는 n의 2진수에 있는 1의 개수와 같습니다.
    4. 
            
  4. 연결합병 정렬은 크기가 반인 부분 문제 두 개를 풀어야 하지만, 거듭제곱은 같은 부분 문제 하나의 답을 두 번 쓰면 됩니다. 그 답을 변수 half에 저장하지 않고 power(a, n // 2)를 두 번 부르면, 호출 수가 층마다 두 배로 늘어 결국 곱셈 횟수가 반복문과 비슷하거나 오히려 많아집니다. 분할 정복의 효율은 부분 문제의 개수, 크기가 줄어드는 비율, 결합 비용이 함께 정합니다.
    5. 
            
  5. 적용a = 3, n = 13에서 한 단계씩 실행하며 호출이 쌓였다가 아래에서부터 값이 돌아오는 순서를 확인하세요. n을 1000으로 놓고 세 방법의 곱셈 횟수를 비교하세요. n = 1023과 n = 1024 중 한 번 호출 방법의 곱셈이 더 많은 쪽은 어디이고, 왜 그런지 2진수로 설명해 보세요.
    6. 
            
  6. 판단곱셈 횟수가 줄었다고 실행 시간이 꼭 그만큼 주는 것은 아닙니다. 3¹⁰⁰⁰은 478자리 수라서 곱셈 한 번도 작은 수의 곱셈보다 훨씬 오래 걸립니다. 그래도 같은 수를 반복해서 곱하는 방법보다는 훨씬 빠르며, 암호에서 쓰는 "aⁿ을 m으로 나눈 나머지" 계산은 매 단계 나머지만 남겨 수가 커지지 않게 하면서 이 방법을 그대로 씁니다(파이썬의 pow(a, n, m)).
    7.
