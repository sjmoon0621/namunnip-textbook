빅오 표기법과 복잡도

자료가 1,000개일 때 0.01초 걸린 프로그램이 100만 개에서는 몇 초 걸릴까요? 답은 알고리즘에 따라 두 배 남짓에서 백만 배 이상까지 달라집니다. 연산 횟수가 늘어나는 빠르기를 한 글자로 요약하는 방법이 빅오 표기법입니다.

3.6.1

입력이 두 배가 되면 연산은 몇 배가 될까?

복잡도 · 연산 횟수 세기와 빅오 표기법

알고리즘

입력 자료

예상 f(n) — 비율 연산 수/f(n)이 일정해지는 것을 고르세요


              

              
브라우저에서 같은 알고리즘을 실제로 실행해 강조한 줄(비교 또는 검사)이 실행된 횟수를 셉니다. 탐색은 찾는 값이 없는 경우(최악)입니다. 시간은 이 컴퓨터에서 잰 값이라 매번, 기기마다 다릅니다.

            

          

          
    
            
  1. 질문정렬 프로그램이 자료 1,000개를 0.01초에 처리했습니다. 자료가 100만 개가 되면 몇 초 걸릴까요? 1,000배라고 답하기 쉽지만, 알고리즘에 따라 2,000배쯤일 수도(O(n log n)), 100만 배일 수도(O(n²)) 있습니다.
    2. 
            
  2. 복원알고리즘의 효율은 실행 시간 대신 기본 연산(비교, 덧셈, 배열 접근 등)의 횟수로 셉니다. 시간은 컴퓨터와 언어에 따라 달라지지만 연산 횟수는 알고리즘만으로 정해지기 때문입니다.
    3. 
            
  3. 설명입력 크기 n에 대한 연산 횟수 T(n)이 충분히 큰 n에서 언제나 c·f(n)보다 작거나 같도록 하는 상수 c가 있으면 T(n) = O(f(n))이라 씁니다(빅오 표기법). 그래서 3n² + 5n + 7은 O(n²)입니다. 가장 빨리 자라는 항만 남기고 상수 계수는 버립니다. 실제로는 T(n)/f(n)이 n이 커져도 일정한 값 근처에 머무는 f(n)을 찾으면 됩니다.
    4. 
            
  4. 연결n이 두 배가 될 때 연산 수가 거의 그대로면 O(log n), 2배면 O(n), 2배보다 조금 크면 O(n log n), 4배면 O(n²)입니다. O(2ⁿ)은 n이 1만 늘어도 2배가 됩니다. 이 ‘두 배 실험’은 코드를 몰라도 측정으로 복잡도를 추정하는 방법이며, 같은 문제를 푸는 두 알고리즘(버블 정렬과 병합 정렬, 선형 탐색과 이진 탐색)을 비교하는 기준이 됩니다.
    5. 
            
  5. 적용버블 정렬에서 예상 f(n)을 n, n log₂ n, n²로 바꿔 가며 ‘연산/f(n)’ 열이 일정해지는 것을 찾으세요. 그다음 입력을 ‘이미 정렬됨’으로 바꾸면 어떻게 되나요? 병합 정렬과 이진 탐색의 f(n)도 찾고, 측정 시간 열이 연산 수와 같은 비율로 늘어나는지 확인하세요.
    6. 
            
  6. 판단빅오는 n이 클 때의 증가율만 말해 줍니다. 상수 계수와 작은 항을 버리므로, n이 작을 때는 O(n²) 알고리즘이 O(n log n)보다 빠를 수도 있습니다. 같은 알고리즘도 입력에 따라 연산 수가 달라지므로(최선·평균·최악), 보통은 최악의 경우로 표기합니다. 측정 시간은 캐시, 다른 프로그램, 타이머 해상도 때문에 흔들리므로 작은 n의 시간으로 복잡도를 판단하면 안 됩니다.
    7.

          3.6.2
빠른 컴퓨터를 사면 느린 알고리즘을 따라잡을 수 있을까?
복잡도 · 증가율 비교와 상수 계수
        

        

          

            
            

              

                
                
              

              

                
                
                
                
                

              

              

                
                
                
                
                

                  
A와 B가 같아지는 n
—

                  
n = 100에서 빠른 쪽
—

                  
n = 10⁶에서 B / A
—

                

              

              
연산 하나에 걸리는 시간을 똑같다고 본 단순 계산입니다. 실제 프로그램의 속도는 언어, 메모리 접근, 입력 자료에 따라 달라집니다.

            

          

          
    
            
  1. 질문O(n²) 정렬을 쓰는 프로그램이 느려서, 1,000배 빠른 컴퓨터를 샀습니다. 이제 O(n log n) 정렬을 쓰는 오래된 컴퓨터보다 빠를까요? 2ⁿ번 연산하는 완전 탐색은 컴퓨터가 빨라지면 얼마나 더 큰 n을 풀 수 있을까요?
    2. 
            
  2. 복원빅오 표기법은 n이 커질 때 연산 횟수가 늘어나는 빠르기(증가율)를 나타내며, 상수 계수와 작은 항은 버립니다. 빠른 순서는 O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)입니다.
    3. 
            
  3. 설명그래프는 두 축이 모두 로그 눈금이라 거듭제곱 함수 nᵏ는 기울기가 k인 직선이 됩니다. n² 직선은 n 직선보다 두 배 가파르고, 2ⁿ은 곧바로 위로 꺾여 올라갑니다. 1초에 10억 번 연산하는 컴퓨터로도 n = 100에서 2ⁿ번 연산하려면 우주의 나이보다 훨씬 긴 시간이 걸립니다.
    4. 
            
  4. 연결컴퓨터가 1,000배 빨라지면 1초 안에 풀 수 있는 n은 O(n)이면 1,000배, O(n²)이면 약 32배(√1000), O(2ⁿ)이면 고작 10 정도(2¹⁰ ≈ 1000) 늘어납니다. 그래서 큰 문제에서는 하드웨어보다 알고리즘을 바꾸는 효과가 훨씬 큽니다. 반면 n이 작으면 상수 계수가 작은 O(n²) 알고리즘이 더 빠를 수 있어, 실제 정렬 라이브러리 중에는 작은 구간을 삽입 정렬로 처리하는 것도 있습니다.
    5. 
            
  5. 적용‘증가율 비교’에서 n을 10⁶까지 올리고 표의 시간을 읽으세요. 속도를 1,000배(10⁹ → 10¹²)로 올려도 1초를 넘는 것은 무엇인가요? ‘상수 계수의 영향’에서 A의 계수를 크게 해도 아주 큰 n에서 B가 결국 느려지는지, 두 알고리즘이 같아지는 n이 어떻게 움직이는지 확인하세요.
    6. 
            
  6. 판단“O(n log n)이 O(n²)보다 언제나 빠르다”는 틀린 말입니다. 빅오는 충분히 큰 n에서의 비교이고, 어디서부터 큰 n인지는 상수 계수가 정합니다. 또 연산 횟수가 같아도 메모리 사용량, 구현의 단순함, 입력의 특징이 알고리즘 선택에 영향을 줍니다.
    7.
